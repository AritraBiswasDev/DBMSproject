📐 Mathematical Architecture & In-Database Novelty
1. Haversine Great-Circle Trigonometry

To compute instantaneous physical distance between consecutive ATM card swipes, the database uses spherical trigonometry:

d = 2R × arcsin(√(sin²(Δφ/2) + cos(φ&sub1;)cos(φ&sub2;)sin²(Δλ/2)))
Velocity (v) = Δd (km) / Δt (hours)

If v > 500 km/h, physical human travel is impossible without supersonic transport, establishing unambiguous fraud evidence.

2. SQL Window Function Temporal Partitioning

The database performs stateful temporal analysis without slow multi-table joins using SQL window functions:

LAG(atm_id, 1) OVER (PARTITION BY card_id ORDER BY transaction_date)
LAG(transaction_date, 1) OVER (PARTITION BY card_id ORDER BY transaction_date)

📐 Relational Inventory Theory & Mathematical Formulations
1. Inventory Reorder Point (ROP) & Safety Stock

To prevent ATM cash-outs without holding excessive idle currency ("Cost of Float"), the relational engine implements inventory reorder point formulas directly in SQL:

Reorder Point (ROP) = (Daily Burn Rate × Lead Time) + Safety Stock
Days to Stockout = Current Physical Cash / Daily Burn Rate

When cash level drops below min_threshold_level or Days ≤ 1.5, an automated CIT dispatch order is inserted into cash_replenishments.

2. Multi-Period Moving Average SQL Window Functions

Rather than relying on static estimates, dynamic cash depletion velocity is evaluated over sliding historical withdrawal partitions:

AVG(daily_cash_dispensed) OVER (
  PARTITION BY atm_id ORDER BY tx_date
  ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
) AS moving_avg_burn_3d

This filters high-frequency noise while detecting genuine demand accelerations (e.g., festivals or paydays) in real time.

⛓️ DBMS Novelty 3: In-Database Cryptographic Tamper-Proof Audit Trail (Merkle Hash Chaining in SQL)

The Rogue DBA & Insider Threat Defense: Conventional databases have no defense against a privileged administrator running UPDATE transactions SET amount = 9999 WHERE transaction_id = 1002;. In this architecture, every transaction stores a mathematically chained prev_hash (pointing to the prior row's SHA-256) and a deterministic row payload entry_hash. Using SQLite window function LAG(entry_hash) OVER (ORDER BY transaction_id), unauthorized alterations are detected instantaneously without needing full database backups!
